## 🛡️ Noor Connect 2.6.0

### 🔍 Hadith Verification (new feature)

* **Paste a hadith → get its source and grade**: a new "Hadith Verification" screen compares pasted text against **all 52,328 hadiths** in the app's 16 collections and returns the closest matches with collection, book, hadith number, authenticity grade and a link that opens the exact hadith in the reader.
* **Runs entirely on-device**: the match uses a prebuilt MinHash fingerprint index (one-time download, ~15–30 ms per scan) — no server, no API, the pasted text never leaves the phone. Normalization strips diacritics and unifies letter forms, so freshly typed text without diacritics still matches at 100%, and half-missing texts still rank their true source at the top.
* **Works in Arabic AND English**: a second index over the English translations (~47,000 hadiths) is matched automatically when the paste is in English — results from both corpora merge, so a paste can surface the Arabic matn and its English translation.
* **Live verification**: results re-compute automatically as you type, with a progress bar for the one-time index download, recent-check history, and share / copy-citation on every match.
* Honest UX throughout: similarity strength labels (Strong / Likely / Possible) instead of false certainty, an explicit note that computational matches are pointers — not scholarly verdicts — and a clear "no close match" state. Every displayed match is **exactly confirmed against the real hadith text**, never just estimated.

### 🕌 Linux Adhan Scheduler (desktop)

* **The adhan now fires while the app is closed on Linux**: the desktop build schedules every prayer for the next 7 days as **systemd user timers** (no root needed) that play the bundled adhan audio via mpv — the Linux equivalent of the Android NativeAdhanScheduler. Survives reboots (Persistent=true), auto-regenerates whenever the app opens or adhan settings change, and honours the per-prayer toggles. Requires mpv for audio playback (declared in the deb dependencies).

### 📖 Hadith Library Fixes

* **Collection and book pages could silently render empty** after a transient data-load failure (the static fallback carries no books) — both now retry automatically and show a real error card with a Retry button instead of a blank list or a misleading "Book Not Found".
* Removed the duplicated "Hadith of the Day" card from the collections page (the daily-hadith page already shows it).

### 🌐 Translation Progress (Phase 1)

* **Arabic-first hadith**: with the app language set to Arabic, the English translation is hidden and the authentic Arabic matn stands alone — it's already in the dataset, so this adds zero size.
* **Tafsir auto-select**: with no stored preference, the commentary edition matching the app language opens by default (Arabic users get Ibn Kathir Arabic). A manually chosen edition now also **persists** — previously it reset on every visit.
* New note under the language setting (all 8 languages) making clear the interface is fully translated while long-form content is progressively translated.

### 🚨 Critical Android fixes (found & reported by Daniel)

* **Crash loop fixed — "Maximum limit of concurrent alarms 500 reached"**: with all reminders enabled, the prayer scheduler requested up to **600 simultaneous Android alarms in one batch** (30 days × 5 prayers × at-time + pre + post + end reminders) plus 150 native adhan alarms — Android caps an app at 500 concurrent alarms and throws a fatal, uncaught exception, so the app crashed on every launch (10 crashes in the submitted log). Pre/post/end reminders now use a 7-day window (the daily reschedule regenerates them), and the batch is hard-capped at 300 with the least-urgent distant reminders trimmed first — worst case ~470 of 500.
* **Content no longer hides under the status bar on Pixel/Android 15+**: apps targeting SDK 35+ are forced edge-to-edge, so the app drew underneath the system status bar ("Settings" behind the clock). The WebView is now shifted down by the real system-bar/cutout inset in `MainActivity` (and the inset is consumed so CSS safe-area padding can never double-apply). No effect on pre-Android-11 devices, which never draw edge-to-edge.

### 🛡️ Privacy & Permissions Page Rework

* **Location permission now actually works on Android**: the page used the browser's geolocation/permissions APIs, which cannot see the Android runtime permission inside the WebView — the status was stuck on "Action needed" even after granting in the OS settings, and "Enable location" silently failed on many devices. Native now uses a tiny in-app Android bridge (`LocationPermissionPlugin` — pure framework APIs, no Google services, still F-Droid compliant) for the live permission check (it can even tell "denied forever" apart from "not asked yet"), the runtime request dialog, and a live re-check after it (some OEM dialogs resolve stale).
* **The page updates itself**: permission status now refreshes automatically when you return from the OS settings (via the Android app-state signal) — previously it stayed stale until a full reload.
* **Redesigned to match the app**: `rounded-2xl` cards, tinted status notes and full dark-mode support (the old light-only color chips washed out in the dark theme).

### 🌙 Ramadan & Eid Calendar Fixes

* **One shared Hijri calendar for everything**: the service worker and the app's offline fallback now use the same tabular Hijri math (`src/lib/hijri-tabular.ts`, verified exact against known 1447 dates: 1 Ramadan = Feb 18, 1 Shawwal = Mar 20, 10 Dhul Hijjah = May 27 2026). This replaces the service worker's linear year-estimate entirely.
* **Eid al-Adha fired a month early**: the estimate added only 70 days to the Ramadan start (lands in Dhul Qadah) instead of ~97 (10 Dhul Hijjah) — in 2026 the service worker greeted users with "Eid-ul-Adha" on **April 29** instead of ~May 27.
* **Ramadan countdown & Eid greetings silently died after 2026**: the year-estimation applied the Hijri drift to a *fixed 2026 base date* without advancing the year.
* **Hardcoded "1447 AH"** in the countdown body — the Hijri year is now derived from the actual target date.
* **Eid al-Adha prep surface added**: the Eid-prep notification now also fires on **Dhul Hijjah 8–9 (including the Day of Arafah)**, and the checklist page accepts Arafah as its prep day — in all 8 languages.
